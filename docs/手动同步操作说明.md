# 手动同步操作说明

> 适用场景：日常自动同步（Windows 任务计划）之外，需要手动补一次数据同步。
> 更新日期：2026-08-31（eloboard 新版 API 架构）

## 一、最简单的方式：双击运行

**双击项目根目录的 `run-sync-hidden.vbs` 即可。**

执行链路（全自动，无需任何前置操作）：

```
run-sync-hidden.vbs          以隐藏窗口方式启动（全程不弹黑框）
  └─ run-sync.bat              切换到项目目录，日志追加写入 sync-local.log
       └─ node local-sync.js   实际同步逻辑：
            ① 自动启动专用 Chrome（.sync-chrome/ profile，过 Cloudflare 盾）
            ② 调用 eloboard 新版 JSON API 抓取选手数据
            ③ 写入本地 data/players/
            ④ 自动关闭专用 Chrome
            ⑤ 推送数据到服务器（local.config.json 中的地址）
```

### 运行模式说明

双击 VBS 走的是**默认增量同步**：

- 只同步近 14 天有比赛的活跃选手（休眠选手自动跳过）
- 新比赛**追加**进本地库，历史数据永久保留
- 若距上次全量同步超过 7 天，会自动转为全量兜底

### 耗时参考

| 模式 | 选手数 | 耗时 |
|------|--------|------|
| 增量 | 仅活跃选手（约 10–20 人） | 1–3 分钟 |
| 全量 | 60 人 | 约 5 分钟 |

## 二、如何确认同步成功

**全程无窗口，唯一可靠依据是日志文件 `sync-local.log`。**

1. 用记事本打开项目根目录的 `sync-local.log`
2. 找到最新一条 `===== 日期 时间 =====` 分隔线（每次运行的起始标记）
3. 检查该段落内的关键输出：

| 日志内容 | 含义 |
|----------|------|
| `✓ 过盾状态就绪` | Chrome 已成功通过 Cloudflare 验证 |
| `=== 增量同步：N 个活跃选手 ===` | 本次同步的选手范围 |
| `✓ 上传成功：服务器已写入 N 个选手数据` | 数据已推送到服务器 |
| `全部完成 2026/8/31 ...` | 本次同步正常结束 |

⚠️ 常见陷阱：**任务计划/双击运行即使失败，也可能显示"成功"**（退出码为 0）。
所以不要相信运行结果提示，**必须看日志**。如果最新 `=====` 段落里
没有 `全部完成`，或出现 `⚠` / `Error` 字样，就是失败了。

## 三、进阶用法（命令行）

打开命令行（cmd 或 PowerShell），执行：

```bat
cd /d D:\WorkSpace\scplayer-stats
```

然后按需选择：

### 1. 强制全量同步（所有 60 名选手）

```bat
node local-sync.js --full
```

适用：怀疑增量漏数据、网站数据结构变动后核对、定期兜底。

### 2. 只同步指定选手（测试用）

```bat
node local-sync.js 12 33
```

参数为选手的 wrId（数字）。适用：验证某位选手的数据是否正常。

### 3. 只同步、不上传服务器

```bat
node local-sync.js --no-upload
```

适用：服务器暂时不可达，或只想本地核对数据。

### 4. 跳过抓取、直接补传本地数据

```bat
node local-sync.js --upload-only
```

适用：之前用了 `--no-upload`，服务器恢复后补传。

### 5. 只下载选手头像

```bat
node local-sync.js --avatars-only
```

适用：新选手入库后补头像（eloboard 外链被拦，头像需本地化）。

### 6. 重建选手 ID 映射

```bat
node local-sync.js --rebuild-id-map
```

适用：修改了 `docs/韩国选手个人主页列表.md`（增删选手）之后。
正常情况下映射文件缺失时同步前会自动重建，一般无需手动执行。

## 四、注意事项

1. **无需手动启动 Chrome**：脚本自动启动/关闭专用 Chrome 实例，
   不影响日常使用的浏览器。同步期间任务栏不会显示 Chrome 窗口（已做隐藏处理）。
2. **不要并发运行**：若任务计划刚好在同步，等它跑完再手动执行
   （日志中出现两条相邻的 `=====` 且第一条没有 `全部完成` 即说明重叠了）。
3. **服务器配置**：上传目标地址和 token 保存在 `local.config.json`
   （不入 git），格式：`{ "server": "http://服务器IP:3001", "token": "..." }`。
   token 需与服务器 `data/upload-token.txt` 一致。
4. **数据安全**：同步只追加新比赛，历史数据有防回退保护，
   新解析字段为空时保留旧值，不会覆盖丢数据。

## 五、常见问题

| 现象 | 原因与处理 |
|------|------------|
| 日志无新增 `=====` 段落 | 脚本根本没跑起来：确认双击的是项目目录下的 vbs，且 `node` 命令可用 |
| 日志出现 `非 JSON 响应` / 入口页失败 | Cloudflare 盾未过：等 30 分钟重试；连续失败可先手动打开一次 eloboard.com 再同步 |
| `上传失败` / 连接超时 | 服务器不可达或 token 不符：检查服务器状态和 `local.config.json`，恢复后用 `--upload-only` 补传 |
| 本地有数据但网页没更新 | 只完成了抓取没完成上传：看日志是否有 `✓ 上传成功`，没有则补传 |
| 想核对数据是否最新 | 对比本地 `data/players/{wrId}.json` 里最新比赛日期与 eloboard 官网选手页，或运行 `node verify-migration.js` |
